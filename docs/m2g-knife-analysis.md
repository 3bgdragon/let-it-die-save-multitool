# M2G 나이프: DB 전용 보정 범위

분석일: 2026-09-09. 설치된 오프라인판 DB 및 로컬 게임 스크립트를 읽기 전용으로 확인했다.

## 하향과 보정의 의미

[공식 2026-09-01 패치 공지](https://letitdie.jp/offline/info/sonih200000008kw.html)는 M2G 나이프의 위력·내구도·탄환 소비 조정을 명시한다. 공지에는 피해 하락률 숫자가 없다. 사용자가 제시한 50% 하락을 상쇄하도록 현행 공격 배율 100을 200으로 설정한다. 온라인판 DB 원본을 대조한 복원이나 최종 실피해량 측정 결과로 표현하지 않는다.

## 피해 배율의 연결

- `BrgProjectile_RedNapalmKnife` 기본 `mAttackInfo.DbAttackID`: `ANI_CH_ATK_WP56_Fire_03`.
- `InitializeSpawn`은 현재 무기 속성 enum 4이면 `ANI_CH_ATK_WP56_FF_Fire_03`을 사용한다.
- 설치 DB에서 두 행의 `scale`은 각각 100이다. 다른 열(STR/DEX 가중치 70/30, 경직·가드·스태미나 등)은 보존한다.
- `master_part`의 WP056 001/005는 일반 에셋, 0H1/0H5는 7002 에셋을 사용하며 두 에셋 모두 Weapon56 애니메이션을 참조한다. 일반/FireFly의 강화 단계별 기본 공격력을 수정할 필요 없이 나이프 공격 정의를 보정한다.
- 라이플·샷건·폭발물·레이지 정의와 탄환/내구도 상수는 그대로 둔다. 현행 나이프 탄환 소비는 6, 내구도 소비 상수는 18이다.
- 공유 DB이므로 같은 공격 정의를 사용하는 NPC도 영향을 받을 수 있다. 플레이어만 구분하는 기능이 아니다.

## DB만으로 나이프 전용 발사를 넣지 않은 이유

1. `BrgDatabaseParam.DatabaseParamInit`은 숙련도 10의 여섯 탄종 구간을 `REDNAPALM_LV10_RANGE_*`에서 읽는다. 현행 순서는 라이플 6, 샷건 6, 나이프 4, 유탄 4, 폭죽 7, 로켓 3이다. 숙련도 1/6의 나이프 구간은 DB 조회 없이 코드에서 0으로 설정한다.
2. `SelectRedNapalmGunBullet`은 0인 구간을 건너뛰고 룰렛 위치에 해당하는 탄종을 선택한다. 다른 다섯 구간을 0으로 만들면 나이프만 선택할 수는 있다.
3. 그러나 `IsCanFireRedNapalmGun`은 플레이어 조준 중, 재장전 요청이 없으며 마지막 발사 탄종과 현재 탄종이 같으면 발사를 거부한다.
4. `UpdateRedNapalmGunRoulette`은 선택 탄종이 마지막 발사 탄종과 달라질 때 마지막 발사 기록을 해제한다. 다른 구간이 없으면 일반적인 룰렛 회전으로 해제되지 않는다.
5. 따라서 단순 DB 고정은 정상적인 나이프 전용 연속 사격이 아니다. 다른 공격의 피해를 0으로 바꾸는 방식도 실제로 나이프를 발사하는 것은 아니므로 사용하지 않는다. 스크립트 수정은 사용자가 지정한 DB 전용 범위 밖이므로 수행하지 않는다.

검사한 핵심 함수의 논리 오프셋/길이(16진수): 선택 `12cbf71/12f`, 룰렛 `12cc1c0/375`, 발사 가능 검사 `12cc5d2/94`, 나이프 초기화 `14a552c/c7`. 해당 구간을 설치된 압축 UPK에서 메모리로 해제해 분석용 캐시와 바이트 일치를 확인했다. 게임 파일은 수정하지 않았다. 디컴파일러가 함수 인자와 일부 연산자를 완벽히 표현하지 못하므로 전체 소스 복원으로 주장하지 않는다.

## 검증 및 복원

자동 테스트는 두 배율만 변경되는지, 중복 적용 방지, 개별 복원, 다른 패치 보존, 잘못된 DB·기록 거부, 실패 시 롤백을 검사한다. `dev/test-m2g-db-copy.js`는 전달된 DB의 임시 복사본에만 적용하며 전체 기존 테이블을 비교한다. 실제 게임에서 나이프 피해량을 측정하는 검증은 별도다.
